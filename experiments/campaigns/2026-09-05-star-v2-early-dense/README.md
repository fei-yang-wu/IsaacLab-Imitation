# 2026-09-05 -- Star v2 early phase, dense checkpoints

Rerun every star-v2 arm for the first 200M frames with a checkpoint every
9,830,400 frames (20 iterations of 20,480 x 24), so the convergence curves
have points between the untrained origin and the first 200M checkpoint of the
original run. The original campaign saved every 200M frames, and no
evaluation can recover a checkpoint that was never written.

## What is identical to `2026-08-30-latent-star-v2`

Every arm's interface, rewards, reset selection with the 0.8 -> 0.2 failure
share ramp over 1B frames, termination curriculum (5M-30M), 20,480
environments x 24 steps, optimizer, network sizes, and seed 0. The ramp and
the curriculum key off the step counter, so the first 200M frames follow the
same schedule the original run did.

The tracker binds the ORIGINAL run's pretrained encoder from
`/storage/ice-shared/vip-vwt/scratch-fwu91/archived_data/latent_star_v2_checkpoints/<arm>_seed0/encoder/checkpoints/latest.pt`
(the cadence arms bind the hub's file, as in the original). There is no
pretrain stage. The posterior arms have no encoder file, as in the original.

## What differs

| field | original | this rerun |
|---|---|---|
| `frame_cap` | 5,000,000,000 | 200,000,000 (407 iterations, 200,048,640 frames) |
| `agent.save_interval` | 200,000,000 | 9,830,400 (20 checkpoints) |
| stages | pretrain, lowlevel1, lowlevel2 | lowlevel1 only |
| output root | `/data/latent_star_v2/` (scratch, 300 GB quota) | `/storage/ice-shared/vip-vwt/scratch-fwu91/latent_star_v2_early/` |
| W&B group | `latent-star-v2` | `latent-star-v2-early` |
| run id prefix | `lsv2-` | `lsv2e-` |
| time limit | 15:59:00 | 03:00:00 (the hub trained 5B in 10h10 on one H200) |

The rerun is a fresh training run. Its checkpoints are not the original
run's early checkpoints; its curve joins the original curve at 200M only up
to run-to-run noise. Say so wherever the two are drawn on one axis.

## This config is generated, not written

```bash
pixi run python -m imitation_experiments.pipeline.derive_early_phase_campaign \
    --campaign experiments/campaigns/2026-08-30-latent-star-v2/campaign.yaml \
    --name latent-star-v2-early --wandb-group latent-star-v2-early \
    --frame-cap 200000000 --save-interval 9830400 \
    --output-root /storage/ice-shared/vip-vwt/scratch-fwu91/latent_star_v2_early \
    --archive-root /storage/ice-shared/vip-vwt/scratch-fwu91/archived_data/latent_star_v2_checkpoints \
    --time-limit 03:00:00 \
    --out experiments/campaigns/2026-09-05-star-v2-early-dense/campaign.yaml
```

## Run

```bash
./experiments/campaigns/2026-09-05-star-v2-early-dense/plan_all.sh     # resolve + preflight, no submit
./experiments/campaigns/2026-09-05-star-v2-early-dense/submit_all.sh   # 44 jobs, one per arm
```

Cost: about 44 x (30 min training + startup) on H200, roughly 4.3 GB of
checkpoints per arm (188 GB total) on ice-shared.

## Score

```bash
./experiments/campaigns/2026-09-05-star-v2-early-dense/build_eval.sh          # eval_campaign.yaml
./experiments/campaigns/2026-09-05-star-v2-early-dense/submit_eval.sh hub 0   # plan one arm
```

`eval_campaign.yaml` is generated by `build_curve_eval_campaign` with
`--tree-root` on this rerun's output and `--encoder-root` on the archive.
Rows land in `/data/eval/star_v2_early_curves/` on ICE, kept apart from the
200M-grid corpus (`/data/eval/star_v2_curves/`). Mirror to
`logs/latent_star_v2_early_curves/` locally. Same board and protocol as
`2026-08-31-star-v2-curves`: `bones_testbed4096_v1` clean, seed 0.
